# Phase 0 検証記録

検証用アプリを 12 版重ねて到達した結論。**推測ではなく Pixel 9 Pro XL の実機で確認したもののみ**を記載する。

## 確定した事実

| 事実 | 根拠 |
|---|---|
| 動画レイヤーの上でも実画面がぼける | Shorts 再生中に確認 |
| `TYPE_ACCESSIBILITY_OVERLAY` はタッチを透過する | Android のタッチ遮断ポリシーで「信頼できるウィンドウ」として除外対象 |
| **ウィンドウ alpha はブラーの強さを直接減衰させる** | alpha 0.8 で元画像が 20% 残り、文字が読める |
| 端末はブラー対応 | `ro.surface_flinger.supports_background_blur = 1` |
| システムは動画再生中もブラーを止めない | `isCrossWindowBlurEnabled` が終始 true |
| 250ms のフェードで切り替えの体感が改善する | 主観評価 |
| 判読限界がアプリで 2.5 倍違う | Shorts r=40 / X r=16 |

## 否定された仮説

### R-01「動画再生中はブラーが無効化される」

**起きなかった。** AOSP が挙げる無効化条件のうち「マルチメディアトンネリング」は
主に Android TV 向けの機能で、スマホの通常再生では使われない。

当初これを最大リスクとして Phase 0 のゲートに置いていたが、杞憂だった。

### 「権限ダイアログや電源メニューを覆う」

**起きなかった。** Android のタップジャッキング対策により、
それらの表示中は非システムのオーバーレイが自動的に隠される。
電源メニューは SystemUI なので、通知シェード連動がそのまま効く。

**除外リストの保守という懸念は実質的に存在しない。**

### 「完全に透明なレイヤーが合成から除外される」

**起きなかった。** ベールに薄い赤を乗せる切り分けを入れたところ赤は表示されたので、
レイヤー自体は合成されていた。ブラー指定だけが無視されていた。

## 使えなかった実装

### `FLAG_BLUR_BEHIND` + `LayoutParams#blurBehindRadius`

2 つの症状が同時に出た。

- **スクリーンショットにはぼかしが乗るのに、実画面には乗らない**
- 半径 > 0 のとき、下のアプリへのタッチが死ぬ

AOSP 内部では「背後を暗くする」ディム機構に相乗りしており、
モーダルウィンドウ扱いになって入力を奪う。半径 0（フラグを外した状態）で
タッチが復帰したことから確定した。

**この API は本用途には使えない。**

### `TYPE_APPLICATION_OVERLAY`

システム UI より下のレイヤーなので**通知シェードを構造的に覆わない**という
大きな利点があるが、alpha の制約で詰んだ。

| alpha | ぼけ | タッチ |
|---|---|---|
| 1.0 | 完全 | **遮断される**（Android 12 の untrusted touch） |
| 0.8 | **元画像が 20% 残る** | 通る |

`FLAG_NOT_TOUCHABLE` は untrusted touch の除外条件に入っていない。
判定に使われるのはウィンドウの `alpha` プロパティだけで、
中身のピクセルが透明かどうかは見ていない。

**「強いぼかし」と「タッチ透過」を同時に満たせない。**

## 採用した実装

```
Window#setBackgroundBlurRadius
  ├ 全画面 Dialog（背景ブラーの要件が translucent かつ floating のため）
  ├ TYPE_ACCESSIBILITY_OVERLAY
  ├ alpha 1.0
  ├ 背景ドローアブル #01000000
  └ FLAG_BLUR_BEHIND は付けない
```

通知シェードの背景ぼかしと同じ系統の API。実画面で確実に描画される。

## 通知シェードの扱い

アクセシビリティオーバーレイは通知シェードより上のレイヤーにあるため、
そのままではシェードもぼける。

**SystemUI が前面になったのを検出してブラーを解除する。**
シェードを開いた時点で対象コンテンツから離れているので、
これは回避策ではなく製品としても正しい挙動。

### 復帰の遅れ

シェードを閉じるアニメーションが完了するまで
「SystemUI が前面でなくなった」イベントが届かないため、**約 0.5 秒の空白**が出る。

ログで検証した結果:

- `isCrossWindowBlurEnabled` は false に落ちていない → システム側の問題ではない
- イベント受信から適用まで **2ms** → 処理は速い
- 遅れはすべてイベント到達までの時間

**250ms のフェードで馴染ませることで許容範囲と判断した。**
シェード中にぼかしを 3 割残す案も試作したが、完全解除＋フェードのほうが自然だった。

## 副産物

ベールがアクセシビリティサービスから出るため、以下がすべて不要になった。

- `SYSTEM_ALERT_WINDOW`
- `FOREGROUND_SERVICE`（AccessibilityService が system_server にバインドされて常駐する）
- `WRITE_SECURE_SETTINGS`（モノクロのフォールバックが要らなくなった）

必要な権限は**ユーザー補助と通知だけ**。
