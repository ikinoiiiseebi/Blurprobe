# 要件定義 rev.4

実装済みの内容に合わせた版。方式選択の根拠は [`phase0-findings.md`](phase0-findings.md) を参照。

## 1. 前提

| | |
|---|---|
| 対象端末 | Pixel 9 Pro XL / 1344×2992 / 3.0x / 448×997dp |
| minSdk | 31 |
| 配布 | ADB サイドロード。Play ストアには出さない |
| 対象アプリ | YouTube、X |
| 依存ライブラリ | **ゼロ**。永続化は SharedPreferences |

半径は**物理ピクセル**指定。σ の近似は `σ = 0.57735 × radius + 0.5`。

## 2. 確定した方式

| 項目 | 採用 |
|---|---|
| ブラー API | `Window#setBackgroundBlurRadius` |
| 実装形態 | 全画面 `Dialog` |
| ウィンドウ種別 | `TYPE_ACCESSIBILITY_OVERLAY` |
| ウィンドウ alpha | **1.0**（下げるとブラーが減衰する） |
| 背景ドローアブル | `#01000000` |
| 遷移 | **250ms のフェード** |
| 通知シェード | SystemUI 前面検出で**完全に解除** |

## 3. 半径の上限

実測の判読限界（Shorts 40 / X 16）を **1.5 倍**した値を上限にしている。
限界ちょうどだと「かろうじて読めてしまう」余地が残るため。

| アプリ | 判読限界（実測） | 採用する上限 |
|---|---:|---:|
| YouTube Shorts | 40 | **60** |
| X | 16 | **24** |

## 4. 消費量モデル

消費量 C は**アプリ間で共有**する。アプリごとに分けて持つと、
交互に使うことで永久に猶予帯へ留まれてしまうため（代償行動の封じ込め）。

一方、**到達時間と上限はアプリごとに持つ**。媒体によって「もう十分見た」と
感じる時間が違うため。

```
# 対象アプリが前面のとき、1 秒ごとに加算
C += 1

# 対象外・通知シェード表示中・画面 OFF では減衰（半減期 90 分）
C *= 0.5 ^ (経過秒 / 5400)

# 毎日 04:00 に C = 0

# 猶予はアプリごとの到達時間に比例（つまみを増やさないため）
G[app] = T[app] × 0.30

# 強度 0〜1
p = 0                                   C ≤ G[app]
p = ((C − G[app]) / (T[app] − G[app]))^k  G[app] < C < T[app]
p = 1                                   C ≥ T[app]

# 半径
R = R_MAX[app] × p

既定: k = 2.0
     T = { YouTube: 600秒(10分), X: 420秒(7分) }   ※ 3〜10分で可変
     R_MAX = { YouTube: 60, X: 24 }
```

減衰は**「読むときに経過時間ぶんまとめて適用する」**方式。
サービスが死んでも端末を再起動しても、離れていた時間が正しく反映される。

### 既定値でのふるまい

**YouTube**（到達 10 分 / 上限 60）

| 経過 | 半径 |
|---:|---:|
| 3分 | 0（猶予） |
| 5分 | 5 |
| 6分 | 11 |
| 7分 | 20 |
| 8分 | 31 |
| 10分 | 60 |

**X**（到達 7 分 / 上限 24）

| 経過 | 半径 |
|---:|---:|
| 2分6秒 | 0（猶予） |
| 4分 | 4 |
| 5分 | 8 |
| 6分 | 15 |
| 7分 | 24 |

σ は半径に線形なので体感の劣化は前半に集中する。
k = 1.0（線形）だと序盤で一気に潰れて後半は何も起きない。

## 5. 手動解除

**1 日 1 回だけ**、消費量 C を 0 にリセットできる。

| 状況 | 動作 |
|---|---|
| 今日まだ使っていない | C を 0 に。「ぼかしをリセットしました。解除は1日1回のみです」 |
| 今日すでに使った | 何もしない。「本日の解除は使用済みです。あと◯時間◯分で回復します」 |

回復は 04:00（Veil の一日の区切り）。

C のリセットは強い救済なので回数を絞っている。**使ったこと自体が記録に残る**ので、
毎日使うようならペースが速すぎるという判断材料になる（R-02 の観測）。

操作経路は常駐通知とクイック設定タイルの 2 つ。

## 6. 機能の入切

**止めるのは苦痛に、戻るのは楽に。** 非対称にしている。

| | 操作 |
|---|---|
| 停止 | ボタンを **3 分間押し続ける**。指を離すとやり直し |
| 再開 | タップ 1 回 |

**停止中も視聴時間の記録は続く。** 止めている間に何分見たのかが分からないと、
止めた効果そのものが測れなくなるため。

## 7. 記録

`UsageLog`。Room は使わず SharedPreferences に日別で持つ。
1 日 1 アプリあたり整数ひとつしか要らないため。

消費量 C とは別物。C は「今どれだけぼかすか」を決める**減衰する値**、
こちらは「実際に何分見たか」の**減衰しない記録**。

画面に出るもの:

```
今週      YouTube 3時間12分   X 48分
先週比    YouTube +18%   X −32%
合計      4時間0分（先週比 +6%）
累計      41時間20分
解除      3日連続で未使用
```

- **先週比**は「直近 7 日」対「その前の 7 日」。暦の週で切らないので週の途中でも意味がある
- **解除の連続未使用日数**は、Digital Wellbeing が持たないこのアプリ固有の信号
- 日別データは 120 日で自動的に古いものを捨てる。累計は捨てない

## 8. 機能要件

| ID | 要件 | 状態 |
|---|---|---|
| FR-01 | 対象アプリの前景状態を検出する | **仮実装**（Shorts と通常動画を区別していない） |
| FR-02 | 滞在秒数を計測し C に加算 | 実装済（スワイプ計数は未） |
| FR-03 | C → 強度 → アプリ別 `R_MAX` → 半径 | 実装済 |
| FR-04 | 半径の変更は 250ms かけて遷移 | 実装済 |
| FR-05 | SystemUI 前面中はブラーを解除 | 実装済 |
| FR-06 | 減衰と 04:00 リセット | 実装済 |
| FR-07 | 安全装置（通知・タイル・プロセス終了時の破棄） | 実装済 |
| FR-08 | 視聴時間の記録と先週比 | 実装済 |
| FR-09 | ペースをアプリ別に調整 | 実装済 |
| FR-11 | 3 分長押しでの機能停止 | 実装済 |
| FR-12 | 1 日 1 回の手動リセット | 実装済 |

**FR-10（週次の再調整通知）は削除。** 画面を開けば先週比が出るので、
通知で促す必要がなくなった。

## 9. 非機能要件

| ID | 項目 | 基準 |
|---|---|---|
| NFR-01 | プライバシー | `INTERNET` を宣言しない。画面内容の読み取りは判定に必要な最小限 |
| NFR-02 | バッテリー | 1 日あたり 3% 以内。自己運用で確認 |
| NFR-03 | 検知遅延 | 対象状態への遷移検出が 500ms 以内 |
| NFR-04 | 描画負荷 | 定常状態では半径を変更しない。変更は遷移中のみ |
| NFR-05 | 復帰性 | サービス停止から 60 秒以内に自動復帰 |
| NFR-06 | 対応範囲 | minSdk 31。検証は Pixel 9 Pro XL 実機のみ |
| NFR-07 | 保守性 | ビュー ID は外部 JSON に分離（M3 で対応） |
| NFR-08 | 依存 | **外部ライブラリを増やさない** |

## 10. 権限

| 権限 | 付与方法 |
|---|---|
| AccessibilityService | 設定 → ユーザー補助（起動スイッチを兼ねる） |
| `POST_NOTIFICATIONS` | アプリ内で要求 |
| 電池最適化の除外 | 設定から手動 |

`SYSTEM_ALERT_WINDOW` / `FOREGROUND_SERVICE` / `WRITE_SECURE_SETTINGS` は**不要**。

## 11. 懸念

| ID | 懸念 | 重大度 | 状態 |
|---|---|---|---|
| R-01 | 動画上でブラーが描画されない | 解消 | 実機で否定 |
| **R-02** | **慣化でぼかしが無視される** | **致命** | **最大の未解決リスク。**解除の使用頻度と先週比で観測する |
| R-03 | Shorts 判定が YouTube 更新で壊れる | 高 | M3 で対応。一次判定をスクロール挙動にする |
| R-04 | 画面がぼけたまま復帰できない | 解消 | 通知・タイルで実証済 |
| R-05 | サービスが OS に停止される | 中 | 電池最適化の除外 |
| R-06 | 音声だけで消費が続く | 中 | 記録を見て判断 |
| R-07 | 代償行動（別アプリへ移動） | 中 | C をアプリ間で共有 |
| R-08 | Advanced Protection Mode との非互換 | 中 | 有効化されると描画ごと止まる |
| R-09 | GPU コストとバッテリー | 中 | カクつきなし。電池は自己運用で確認 |
| R-13 | シェード復帰時の 0.5 秒の遅れ | 軽微 | 250ms のフェードで許容と判断 |
