# 要件定義 rev.3

Phase 0 の実測を反映した版。方式選択の根拠は [`phase0-findings.md`](phase0-findings.md) を参照。

## 1. 前提

| | |
|---|---|
| 対象端末 | Pixel 9 Pro XL / 1344×2992 / 3.0x / 448×997dp |
| minSdk | 31 |
| 配布 | ADB サイドロード。Play ストアには出さない |
| 対象アプリ | YouTube Shorts、X |

半径は**物理ピクセル**指定。σ の近似は `σ = 0.57735 × radius + 0.5`。

## 2. 確定した方式

| 項目 | 採用 |
|---|---|
| ブラー API | `Window#setBackgroundBlurRadius` |
| 実装形態 | 全画面 `Dialog` |
| ウィンドウ種別 | `TYPE_ACCESSIBILITY_OVERLAY` |
| ウィンドウ alpha | **1.0**（下げるとブラーが減衰する） |
| 背景ドローアブル | `#01000000` |
| 遷移 | **250ms のフェード** |
| 通知シェード | SystemUI 前面検出で**完全に解除** |
| 半径の上限 | **アプリ別**（Shorts 40 / X 16） |

## 3. 段階

判読不能になる半径がアプリで 2.5 倍違ったため、`R_MAX` をアプリごとに持つ。

### YouTube Shorts（R_MAX = 40）

| 段階 | radius | σ | 見え方 |
|---|---:|---:|---|
| S0 | 0 | 0.5 | 干渉なし。猶予帯 |
| S1 | 8 | 5.1 | 輪郭がわずかに滲む |
| S2 | 16 | 9.7 | 小さい文字が読みにくい |
| S3 | 26 | 15.5 | キャプションが判読不能 |
| S4 | 40 | 23.6 | 大きな見出しも判読不能 |

### X（R_MAX = 16）

| 段階 | radius | σ | 見え方 |
|---|---:|---:|---|
| S0 | 0 | 0.5 | 干渉なし |
| S1 | 3 | 2.2 | わずかに滲む |
| S2 | 6 | 4.0 | 読むのに集中が要る |
| S3 | 10 | 6.3 | 拾い読みが困難 |
| S4 | 16 | 9.7 | タイムラインが判読不能 |

## 4. 消費量モデル

消費量 C は**アプリ間で共有**する。アプリごとに分けて持つと、
交互に使うことで永久に猶予帯に留まれてしまうため（代償行動の封じ込め）。

```
# 対象状態が前面のとき、1秒ごとに加算
C += 1 + β × (直近1秒のスワイプ数)        β = 3

# 対象外／画面OFF時は減衰（半減期 90分）
C *= 0.5 ^ (経過秒 / 5400)

# 毎日 04:00 に C = 0

# 強度 0〜1（アプリ共通）
p(C) = 0                            C ≤ G
p(C) = ((C − G) / (T − G)) ^ k      G < C < T
p(C) = 1                            C ≥ T

# 半径（アプリ別）
R = R_MAX[app] × p(C)

既定: G = 180, T = 1200, k = 2.0
     R_MAX = { YouTube Shorts: 40, X: 16 }
```

σ は半径に線形なので、体感の劣化は前半に集中する。
k = 1.0（線形）だと序盤で一気に潰れて後半は何も起きない。
k = 2.0 前後で初めて「じわじわ効く」曲線になる。

## 5. 機能要件

| ID | 要件 | 状態 |
|---|---|---|
| FR-01 | 対象アプリの前景状態を検出する。YouTube は Shorts 表示中のみ、X はタイムライン表示中。検出は 500ms 以内 | 未実装 |
| FR-02 | 滞在秒数と縦スワイプ回数を計測し、消費量 C に加算する | 未実装 |
| FR-03 | C から求めた強度にアプリ別の `R_MAX` を掛けた半径のブラーを適用する | 実証済 |
| FR-04 | 半径の変更は 250ms かけて滑らかに遷移させる | 実証済 |
| FR-05 | SystemUI が前面の間はブラーを解除し、離れたら FR-04 に従って戻す | 実証済 |
| FR-06 | 対象外および画面 OFF 時に C を減衰させ、毎日 04:00 に 0 へリセットする | 未実装 |
| FR-07 | 安全装置：常駐通知の解除ボタン、クイック設定タイル、無操作 10 分での自動解除、プロセス終了時のオーバーレイ破棄 | 実証済 |
| FR-08 | 日次ログを端末内に保存する。滞在時間・スワイプ数・各段階の滞在時間・手動解除の回数・判定不一致の回数 | 未実装 |
| FR-09 | カーブパラメータ（G / T / k / β）とアプリ別 `R_MAX` をアプリ内から変更できる | 未実装 |
| FR-10 | 週に一度、カーブの再調整を促す通知を出す | 未実装 |

## 6. 非機能要件

| ID | 項目 | 基準 |
|---|---|---|
| NFR-01 | プライバシー | `INTERNET` を宣言しない。画面内容の読み取りは Shorts 判定に必要な最小限に限り、テキスト内容は保存しない |
| NFR-02 | バッテリー | 1 日あたり 3% 以内。Phase 1 で確認 |
| NFR-03 | 検知遅延 | 対象状態への遷移検出が 500ms 以内 |
| NFR-04 | 描画負荷 | 定常状態では半径を変更しない。変更は FR-04 の遷移中のみ |
| NFR-05 | 復帰性 | サービス停止から 60 秒以内に自動復帰する |
| NFR-06 | 対応範囲 | minSdk 31。検証は Pixel 9 Pro XL 実機のみ |
| NFR-07 | 保守性 | YouTube・X のビュー ID は外部 JSON に分離し、再ビルドなしで更新できる |

## 7. アーキテクチャ

```
ContextDetector   AccessibilityService。前景パッケージとスクロール挙動から
                  対象状態を判定。SystemUI 検出も兼ねる
      ↓
ConsumptionMeter  滞在秒とスワイプ数を C に加算。離脱時は減衰。Room に永続化
      ↓
VeilPolicy        C から目標半径を決定。SystemUI 前面なら 0 に落とす
      ↓
VeilOverlay       全画面 Dialog。目標値へ 250ms で遷移
      ↓
Recovery          常駐通知・クイック設定タイル・無操作タイマー
```

### 必要な権限

| 権限 | 付与方法 |
|---|---|
| AccessibilityService | 設定 → ユーザー補助 |
| `POST_NOTIFICATIONS` | アプリ内で要求 |
| 電池最適化の除外 | 設定から手動 |

`SYSTEM_ALERT_WINDOW` / `FOREGROUND_SERVICE` / `WRITE_SECURE_SETTINGS` は**不要**。

## 8. 懸念

| ID | 懸念 | 重大度 | 状態 |
|---|---|---|---|
| R-01 | 動画上でブラーが描画されない | 解消 | 実機で否定 |
| **R-02** | **慣化でぼかしが無視される** | **致命** | **最大の未解決リスク。**技術では解けない |
| R-03 | Shorts 判定が YouTube 更新で壊れる | 高 | スクロール挙動を一次判定、ビュー ID を二次判定に |
| R-04 | 画面がぼけたまま復帰できない | 解消 | 三重化で実証済 |
| R-05 | サービスが OS に停止される | 中 | 電池最適化の除外 |
| R-06 | 音声だけで消費が続く | 中 | ログで観測して次版で判断 |
| R-07 | 代償行動（別アプリへ移動） | 中 | C をアプリ間で共有 |
| R-08 | Advanced Protection Mode との非互換 | 中 | 有効化されると描画ごと止まる |
| R-09 | GPU コストとバッテリー | 中 | カクつきは無し。電池は Phase 1 |
| R-13 | シェード復帰時の 0.5 秒の遅れ | 軽微 | フェードで許容範囲と判断 |

### R-02 について

摩擦介入は数週間〜1ヶ月で効果が減衰するという縦断データがある。
対策は 4 つ入れるが、**効くかどうかは 2 週間の自己運用で確かめるしかない。**

1. カーブを非線形にし、前半を無干渉に
2. 対象アプリ外での減衰で「資源」として体感させる
3. 週次で自分にカーブ再調整を促す
4. FR-08 のログで効果を自分で確認できるようにする

## 9. Phase 1 の運用計画

実装後、2 週間の自己運用で以下を観測する。

- 初週はカーブを固定して基準値を取る
- 2 週目に慣化の兆候（同じ段階での滞在時間の増加）が出ているか
- 手動解除が週 3 回を超えるならカーブが厳しすぎる。G と T を緩める
- S4 到達後の滞在時間が長いなら R-06（音声のみの消費）が起きている
- 電池の減りが常用に耐えるか（V-04 の繰り越し）

## 10. スコープ外

- Play ストアでの配布、他人の端末での動作
- Pixel 9 Pro XL 以外での検証
- TikTok・Instagram Reels などの追加
- 音量への介入
- モノクロ化のフォールバック（ブラーが安定して動くため不要）
- iOS 版（オーバーレイの仕組みが存在せず実装不能）
