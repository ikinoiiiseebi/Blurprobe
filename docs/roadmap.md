| | |

| | |
|---|---|

## 残り

### M3 — 判定を本物にする

仮判定を Shorts / X タイムラインの判定に置き換える。

| | 内容 |
|---|---|
| FR-01 | 一次判定＝スクロール挙動（縦フリングの間隔と連続性）、二次判定＝ビュー ID |
| FR-02 | スワイプ計数を追加 |
| NFR-07 | ビュー ID を外部 JSON に分離。再ビルドなしで直せるように |
| — | 判定不一致をログに残し、劣化を検知できるようにする |

**受け入れ条件**

- Shorts と通常の YouTube 動画を 10 回切り替えて誤判定 0
- X のタイムラインと個別ポスト画面を区別できる

**R-03 への備え**：YouTube の更新でビュー ID は必ず変わる。
**ID 依存を単独の判定根拠にしない。** 一次判定だけでも動く状態を保つ。

## 自己運用で見ること

実装と並行して、日常的に使いながら観測する。

| 見るもの | 判断 |
|---|---|
| 先週比が減っているか | 効いている／いない |
| 手動リセットの使用頻度 | 毎日使うならペースが速すぎる |
| 同じ段階での滞在時間 | 延びていれば**慣化（R-02）が起きている** |
| 電池の減り | 常用に耐えるか（V-04 の繰り越し） |

**R-02 が最大の未解決リスク。** 技術の問題は片付いているので、
残っているのは「実際に効くのか」という問題だけ。

## 保留

先回りして実装しない。運用結果を見てから判断する。

| | 判断材料 |
|---|---|
| 音量への介入（R-06） | 最大到達後の滞在時間が長ければ、音声だけで消費が続いている |
| ペースの作り直し | 手動リセットの使用頻度 |
| 「消費したサムネイルが積み上がる」表現 | 当初案。ブラーで十分なら不要 |
| 対象アプリの追加 | まず 2 つで慣化が防げるかを見る |
